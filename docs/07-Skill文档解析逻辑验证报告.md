# 07-Skill 文档解析逻辑验证报告

> 版本：v0.1
> 说明：以真实技能文档「SFHIS Core 住院医嘱问题排查解决技能」为样本，验证 `SKILL.md` 解析逻辑的完整链路，并记录格式调整过程与验证结果。

***

## 一、验证目标

1. 验证 [06-Skill文档入库方案.md](06-Skill文档入库方案.md) 中实现的解析逻辑（`_is_skill_file` / `parse_skill_frontmatter` / `build_skill_docs` / `sync_and_ingest`）。
2. 用真实 skill 文档当样本，暴露格式问题并修复为标准 `SKILL.md`。
3. 端到端验证：识别 → frontmatter 解析 → 正文切分 → 入库 → FTS5 检索命中。

***

## 二、原始文档格式分析

样本原文件：`SFHIS Core 住院医嘱问题排查解决技能.md`（项目根目录）。

对照标准 SKILL.md 规范，发现以下问题：

| # | 问题                                                                                 | 影响                                                        |
| - | ---------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1 | **无 YAML frontmatter**：`name`/`description` 等元信息写在正文「## 技能元信息」章节，用纯文本 `key: value` | `parse_skill_frontmatter` 要求文件以 `---` 开头，无法解析，`name` 提取失败 |
| 2 | **文件名非** **`SKILL.md`**：basename 为中文标题                                             | `_is_skill_file` 只认 basename 为 `skill.md`，无法进入 skill 分支   |
| 3 | **格式污染**：正文含零宽字符（`​`）、反斜杠编号（`\1.`）、`●` 项目符号                                        | 零宽字符会打断中文 bigram 连续段，`\1.` 非标准列表，影响切分与检索                  |
| 4 | FAQ 标题用 `**加粗**` 而非 `#` 标题                                                         | `split_markdown` 仅按 `#` 标题切分，Q1/Q2/Q3 无法切成独立片段            |

***

## 三、格式调整

将原文档调整为标准 `SKILL.md`，位于 `skills/sfhis-core-inhospital-drug-solve/SKILL.md`：

| 调整项         | 调整前                          | 调整后                                                                  |
| ----------- | ---------------------------- | -------------------------------------------------------------------- |
| frontmatter | 正文「## 技能元信息」纯文本              | 文件开头 `---` 包裹的 YAML（含 `name`/`version`/`description`/`type`/`scene`） |
| 文件名         | `SFHIS Core 住院医嘱问题排查解决技能.md` | `skills/<name>/SKILL.md`                                             |
| 项目符号        | `●`                          | `1.` `2.` 有序列表                                                       |
| 编号          | `\1.` `\2.`                  | `1.` `2.`                                                            |
| FAQ 标题      | `**Q1：...**`                 | `### Q1：...` 三级标题                                                    |
| 零宽字符        | 大量 `​`（U+200B）               | 全部清除                                                                 |

> 原中文标题 `SFHIS Core 住院医嘱问题排查解决技能` 保留为正文首个一级标题；`name` 取技能英文名 `sfhis-core-inhospital-drug-solve`。

***

## 四、验证步骤与结果

验证脚本（临时，运行后已删除）依次执行 5 项检查：

### 4.1 文件名识别

```
_is_skill_file('SKILL.md')                                    = True
_is_skill_file('SFHIS Core 住院医嘱问题排查解决技能.md')          = False
```

结论：调整后文件名 `SKILL.md` 可被正确识别；原中文文件名无法识别（验证了问题 #2 的存在与修复）。

### 4.2 frontmatter 解析

```
name        = sfhis-core-inhospital-drug-solve
description = 用户在SFHIS Core系统遇到住院药品医嘱停嘱失败、领药单生成失败、药品未计费等问题时，自动匹配标准排查步骤与解决方案，仅限住院药品相关系统故障处理，严格按照文档标准答案执行，禁止私自新增操作流程。
body 行数    = 56
```

结论：`name`/`description` 正确提取，正文 `body` 完整剥离。

### 4.3 正文切分与片段构建

```
片段数 = 7
  # SFHIS Core 住院医嘱问题排查解决技能
  ## 一、技能执行强制规则 ...
  ## 二、核心FAQ问答库
  ### Q1：药品医嘱无法停医嘱 ...
  ### Q2：领药单生成失败 ...
  ### Q3：药品没有记上费 ...
  ## 三、异常兜底规则 ...
```

结论：`###` 标题化生效，Q1/Q2/Q3 被切成独立片段，`title` 统一为技能 `name`（符合设计）。

### 4.4 端到端同步入库

```
入库片段总数 = 7
```

结论：`SKILL.md` 被并入现有 MD 同步（`sync_and_ingest` 正确分支到 `build_skill_docs`）。

### 4.5 检索命中验证

| 提问        | 命中  | top1 内容      |
| --------- | --- | ------------ |
| 住院药品停医嘱失败 | 1 条 | Q1 药品医嘱无法停医嘱 |
| 领药单库存不足   | 3 条 | Q2 领药单生成失败   |
| 药品漏计费怎么补  | 1 条 | Q3 药品没有记上费   |

结论：`description` 与正文已纳入索引，口语化同义提问可命中对应标准答案。

***

## 五、结论

1. 解析逻辑（`parse_skill_frontmatter` / `build_skill_docs` / `sync_and_ingest` 分支）对**标准格式** `SKILL.md`（`---` frontmatter + 文件名 `SKILL.md`）工作正常。
2. 真实文档常不规范（非 `SKILL.md` 命名、无 frontmatter、格式污染），需先标准化后方可正确入库——本报告已完成该调整。
3. 端到端检索链路验证通过：口语化提问可命中标准答案。

### 已知边界（记录，本次未改动代码）

- `_is_skill_file` 仅按 basename `skill.md` 识别；如需支持中文命名或自定义文件名，后续可扩展识别规则（如检测 frontmatter 是否含 `name`）。

- 标准 skill 目录结构为 `skills/<name>/SKILL.md`；知识库同步时需将 `skills/` 目录纳入 `kb.repo_path` 或 `kb.repo_url`。
