## 一、业务目标与边界

本阶段实现**群聊多消息聚合引擎**（`src/aggregator/buffer.py`），解决"用户在群里连续发多条消息组成一个完整问题"的需求。

**目标**：
1. 仅当群聊首条消息 @ 本机器人（或 @ 配置的指定人）时，才开始聚合；
2. 同一 `userid` 在时间窗（默认 30 秒）内的连续消息拼接为完整问题；
3. 时间窗内其他 `userid` 的插话不中断当前用户的聚合计时（仅忽略）；
4. 时间窗到期后触发检索；若首条消息未 @ 本机器人，整个缓冲丢弃；
5. 聚合完成后把完整问题交给检索应答（阶段 5 接入）。

**边界**：本阶段只实现聚合与 @ 判定，检索/回复逻辑由阶段 5 实现，聚合完成后的处理通过回调函数注入。

## 二、核心算法：时间窗缓冲

### 2.1 缓冲键

- 聚合缓冲区以 `chatid + userid` 为键（同一群内不同用户各自的聚合互不干扰）。

### 2.2 状态

每个缓冲键维护：
- `parts: list[str]` — 已聚合的消息片段；
- `first_req_id: str` — 首条消息的 req_id（回复时透传）；
- `first_at_robot: bool` — 首条消息是否 @ 本机器人；
- `timer: asyncio.TimerHandle` — 时间窗定时器；
- `last_ts: float` — 最后一条消息时间。

### 2.3 算法流程

```
收到群聊消息（chatid, userid, content, req_id）：
1. 判断是否 @ 本机器人（或 @ 指定人）：strip_mention(content)
   - 若缓冲不存在：
     - 未 @ 本机器人 → 丢弃（不建立缓冲）
     - 已 @ 本机器人 → 建立缓冲，去掉 @ 前缀后作为首段，启动时间窗定时器
   - 若缓冲已存在：
     - 直接拼接 content 到当前缓冲，重置/延长时间窗
2. 时间窗到期：
   - 首条未 @ 本机器人 → 丢弃整个缓冲
   - 已 @ → 将完整问题交给检索应答回调，清理缓冲
3. 时间窗内其他 userid 发言：不匹配本缓冲键，不中断聚合计时（仅被忽略）
```

### 2.4 @ 判定与去除

企微群聊回调文本中 @ 机器人以文本形式出现（如 `@RobotA hello robot`）。判定规则：
- 匹配配置的 @ 目标列表（`aggregate.mention_targets`，默认包含机器人名称、`aibotid`）；
- 命中后从文本中去除 `@xxx` 前缀后再聚合，避免把 @ 带进检索问题。

> 说明：企微回调中 @ 的精确文本形态以官方文档/实际回调为准；本阶段实现基于"`@` + 目标名"前缀匹配，若实际形态不同，在联调时校准（标注待验证）。

## 三、接口设计

### 3.1 `strip_mention(content: str, targets: list[str]) -> tuple[str, bool]`

- **用途**：判断消息是否 @ 目标，并去除 @ 前缀。
- **参数**：`content` 原始文本；`targets` @ 目标列表（机器人名/aibotid）。
- **返回**：`(去除 @ 后的文本, 是否命中 @)`。

### 3.2 `class MessageBuffer`

| 接口 | 说明 |
| --- | --- |
| `MessageBuffer(config, on_complete)` | 构造：`on_complete(question, req_id, meta)` 为聚合完成回调 |
| `add(chatid, userid, content, req_id)` | 聚合一条群聊消息 |
| `_start_timer(key, ctx)` | 启动/重置时间窗定时器 |
| `_on_window_expire(key, ctx)` | 时间窗到期：@ 判定后提交或丢弃 |
| `_clear(key)` | 清理缓冲 |

## 四、关键代码逻辑（伪代码）

```python
async def add(chatid, userid, content, req_id):
    key = (chatid, userid)
    cleaned, at_robot = strip_mention(content, targets)
    if key not in self._buffers:
        if not at_robot:
            return  # 首条未 @ 本机器人，丢弃
        ctx = {"parts": [cleaned], "first_req_id": req_id, "at_robot": True}
        self._buffers[key] = ctx
        self._start_timer(key, ctx)
        return
    ctx = self._buffers[key]
    ctx["parts"].append(cleaned)          # 已有缓冲，直接拼接
    self._start_timer(key, ctx)           # 重置时间窗

def _on_window_expire(key, ctx):
    # 时间窗到期：首条未 @ 则丢弃，否则提交完整问题
    if not ctx["at_robot"]:
        self._clear(key)
        return
    question = "".join(ctx["parts"])      # 拼接为完整问题
    self._clear(key)
    await self._on_complete(question, ctx["first_req_id"], {"chatid": key[0], "userid": key[1]})
```

> 并发安全：缓冲访问集中在单事件循环内执行，天然串行；定时器回调与消息处理均在同一 event loop，无需额外加锁。

## 七、验收标准

1. 首条未 @ 本机器人的群聊消息被丢弃，不建立缓冲；
2. 同一 userid 时间窗内连续消息拼接为完整问题；
3. 其他 userid 插话不中断聚合计时；
4. 时间窗到期后触发完成回调并清理缓冲；
5. @ 前缀被正确去除，不进入检索问题；
6. 代码符合规范：中文注释、try/except 指定异常类型、单函数 ≤ 50 行。
