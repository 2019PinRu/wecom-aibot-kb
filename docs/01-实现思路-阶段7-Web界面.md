## 一、业务目标与边界

本阶段实现 **Web UI 四个核心页面**（`src/web/`）与 **FastAPI 应用入口**（`src/main.py`），打通"可视化运维"链路：管理知识库、查看待补充问题、配置系统参数。

**目标**：

1. 四个页面：概览 Dashboard、知识库管理、待补充问题、系统参数；
2. `main.py` 装配配置、数据库、企微接入、Web 路由，作为系统统一入口；
3. `sys_config` 作为运行时动态配置覆盖层（叠加在 config.yaml 之上）；
4. 知识库页可触发阶段 6 的 `sync_and_ingest` 同步。

**边界**：本阶段不实现登录鉴权（内网本地工具，MVP 省略）；不重写既有接入/检索逻辑；Bootstrap 5 走 CDN，不新增依赖。

## 二、页面与路由设计

| 页面           | 路由             | 功能                                             |
| ------------ | -------------- | ---------------------------------------------- |
| 概览 Dashboard | `GET /`        | kb\_docs 片段数、pending\_questions 各状态统计、四个页面快捷入口 |
| 知识库管理        | `GET /kb`      | 片段列表（分页 + 关键词搜索）、查看原文预览、删除单条、触发同步              |
| 待补充问题        | `GET /pending` | 问题列表（状态筛选）、补充答案并标记已处理                          |
| 系统参数         | `GET /config`  | 动态配置键编辑，保存写入 sys\_config                       |

**知识库管理**：

- 列表 SQL 直接查 `kb_docs`（带 `rowid`，用于删除）：`SELECT rowid, title, source, doc_id, substr(raw_content,1,100) AS preview FROM kb_docs ...`；

- 关键词搜索复用 `fts5.build_match_query` 生成 MATCH 条件；

- `POST /kb/sync` 调用 `sync_and_ingest(config)` 全量重建，结果反馈到页面；

- `POST /kb/{rowid}/delete` 删除单条 `DELETE FROM kb_docs WHERE rowid = ?`。

**待补充问题**：

- 列表按 `status`（pending/resolved）筛选；

- `POST /pending/{id}/resolve`：表单提交答案，`UPDATE pending_questions SET status='resolved', answer=?, updated_at=datetime('now','localtime') WHERE id=?`。

**系统参数**：

- 预置可编辑动态键（点分路径 + 中文说明）：`reply.prefix`、`reply.no_answer`、`aggregate.window_seconds`、`retriever.score_threshold`、`retriever.top_k`；

- `POST /config/save` 用 SQLite UPSERT 写入 `sys_config`，并提示"重启生效"（或即时生效说明见下文 2.1）。

### 2.1 动态配置覆盖机制

`sys_config` 作为**运行时覆盖层**，叠加在 config.yaml 之上：

- `Config.overlay_db(db_path)` 新增方法：读取 `sys_config` 全部键值，按点分路径覆盖到配置字典；

- 值类型按现有配置项类型转换（int/float/bool/str），保证 `aggregate.window_seconds` 等仍为数值；

- `main.py` 启动时：`load_config` → `init_db` → `overlay_db`，之后所有组件拿到的是合并后配置；

- 说明：保存后需重启进程生效；MVP 不做热更新（标注待优化）。

## 三、应用入口装配（src/main.py）

`main.py` 作为系统统一入口，装配全链路：

```
create_app(config):
  1. load_config → init_db(db_path)（含阶段6迁移）→ overlay_db(db_path)
  2. 装配组件：
     reply_client   = ReplyClient(max_concurrency)
     responder      = Responder(config, reply_client, db_path)
     single_handler = 单聊：提取 text.content → responder.handle_question(meta=单聊)
     buffer         = MessageBuffer(window, mention_targets, on_complete)
     on_complete    = (question, req_id, meta) → responder.handle_question(..., {**meta, "chattype":"group"})
     group_handler  = 群聊：提取 chatid/userid/content → buffer.add(...)
     dispatcher     = Dispatcher(reply_client, single_handler, group_handler)
     callback       = CallbackClient(config, dispatcher, reply_client)
  3. FastAPI app：挂载 web 路由 + Jinja2 模板
  4. lifespan 启动：已配置 bot_id/bot_secret 时启动 callback，否则仅 Web
```

- `app = create_app()` 供 `uvicorn main:app` 使用；`if __name__ == "__main__"` 内 `uvicorn.run` 支持 `python -m main`。

- `mention_targets` 为空时回退到 `[wecom.bot_id]`。

## 七、验收标准

1. 四个页面均可访问：概览、知识库、待补充问题、系统参数；
2. 知识库页可搜索、删除、触发同步，同步后统计更新；
3. 待补充问题可补充答案并标记已处理；
4. 系统参数保存后写入 `sys_config`，重启后 `Config.get()` 返回覆盖值且类型正确；
5. `main.py` 启动：无机器人凭据时仅 Web 可运行，不抛错；有凭据时启动长连接；
6. 代码符合规范：中文注释、参数化 SQL、try/except 指定异常类型、单函数 ≤ 50 行。
