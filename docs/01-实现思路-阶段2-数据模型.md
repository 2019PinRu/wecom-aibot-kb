## 一、业务目标与边界

本阶段实现系统**数据层**：定义 SQLite 数据库连接与全部表结构，为检索、待补充问题、系统配置提供存储能力。

**目标**：

1. 定义 3 张核心表：知识库 FTS5 表、待补充问题表、系统配置表；
2. 提供数据库初始化（建表）与连接管理；
3. 所有 SQL 使用参数化查询。

**边界**：本阶段只建表与提供基础 CRUD 辅助函数，不涉及检索算法、聚合等业务逻辑。

***

## 二、数据库表设计

### 2.1 `kb_docs`（知识库文档表，FTS5）

存储切分后的知识片段，使用 SQLite FTS5 虚拟表提供全文检索。

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS kb_docs USING fts5(
    title,              -- 文档标题
    content,            -- 文档内容（切分后的片段）
    source,             -- 来源（如 git 仓库路径/文件名）
    doc_id,             -- 源文档唯一标识
    tokenize = 'unicode61'
);
```

> 说明：FTS5 虚拟表与业务表分离；`doc_id` 用于去重与关联源文档。

### 2.2 `pending_questions`（待补充问题表）

记录检索无结果或低置信度的问题，供管理员补充答案。

| 字段          | 类型                                         | 说明                     |
| ----------- | ------------------------------------------ | ---------------------- |
| id          | INTEGER PRIMARY KEY AUTOINCREMENT          | 自增主键                   |
| question    | TEXT NOT NULL                              | 原始问题文本                 |
| asker       | TEXT                                       | 提问人 userid（可能加密，原样存储）  |
| chattype    | TEXT                                       | single / group         |
| chatid      | TEXT                                       | 群聊会话 id（单聊为空）          |
| status      | TEXT DEFAULT 'pending'                     | pending 待处理 / done 已处理 |
| answer      | TEXT                                       | 管理员补充的答案（处理后写入知识库）     |
| created\_at | TEXT DEFAULT (datetime('now','localtime')) | 创建时间                   |
| updated\_at | TEXT                                       | 更新时间                   |

```sql
CREATE TABLE IF NOT EXISTS pending_questions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    question TEXT NOT NULL,
    asker TEXT,
    chattype TEXT,
    chatid TEXT,
    status TEXT NOT NULL DEFAULT 'pending',
    answer TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    updated_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_pending_status ON pending_questions(status);
```

### 2.3 `sys_config`（系统配置表）

Web 界面可动态修改的配置项，覆盖 `config.yaml` 中可配置项（回复前缀、无结果话术、聚合时间窗、FTS5 阈值等）。

| 字段          | 类型               | 说明                       |
| ----------- | ---------------- | ------------------------ |
| key         | TEXT PRIMARY KEY | 配置键（点分路径，如 reply.prefix） |
| value       | TEXT             | 配置值                      |
| updated\_at | TEXT             | 更新时间                     |

```sql
CREATE TABLE IF NOT EXISTS sys_config (
    key TEXT PRIMARY KEY,
    value TEXT,
    updated_at TEXT
);
```

> 优先级：`sys_config`（运行时动态）> 环境变量 > `config.yaml` > 默认值。动态配置合并逻辑在后续 Web 阶段实现，本阶段仅建表。

## 三、接口设计

### 3.1 `get_connection(db_path: str) -> sqlite3.Connection`

- **用途**：获取 SQLite 连接。

- **参数**：`db_path` 数据库文件路径。

- **返回**：配置好 `row_factory` 与 WAL 模式的连接。

- **说明**：确保父目录存在；调用方负责 try/except 与关闭。

### 3.2 `init_db(db_path: str) -> None`

- **用途**：初始化数据库，创建全部表。

- **参数**：`db_path` 数据库文件路径。

- **返回**：无。

- **说明**：幂等（`IF NOT EXISTS`）；所有建表语句在单个事务中执行。

### 3.3 `execute(db_path: str, sql: str, params: tuple = ()) -> int`

- **用途**：执行单条写 SQL。

- **参数**：`db_path` 路径；`sql` 参数化 SQL；`params` 参数元组。

- **返回**：受影响行数。

- **说明**：内部 try/except，失败时记录日志并回滚。

### 3.4 `query(db_path: str, sql: str, params: tuple = ()) -> list[dict]`

- **用途**：执行查询 SQL。

- **参数**：同 `execute`。

- **返回**：字典列表（`row_factory = sqlite3.Row`）。

## 四、关键代码逻辑（伪代码）

```python
def init_db(db_path):
    """初始化数据库，创建知识库/待补充/配置三张表。"""
    conn = get_connection(db_path)
    try:
        with conn:
            conn.executescript(_SCHEMA_SQL)   # 建表 SQL（IF NOT EXISTS，参数化不适用，故用 executescript）
    except sqlite3.Error as exc:
        logger.error("初始化数据库失败: %s", exc)
        raise
    finally:
        conn.close()
```
