# 05-知识库内容补充方案与操作指南

> 版本：v0.1
> 说明：本文档解决「无外部知识库来源、无法人工补充知识库内容」问题，涵盖补充渠道设计、代码实现点与分渠道操作流程。

***

## 一、现状与问题

改造前，系统只有两条知识来源链路：

| 现有能力                 | 入口                                | 局限                                   |
| -------------------- | --------------------------------- | ------------------------------------ |
| Git / 本地 Markdown 同步 | 配置 `kb.repo_url` 或 `kb.repo_path` | 两个都为空时 `sync_and_ingest` 直接跳过，入库 0 条 |
| 待补充问题闭环              | 用户提问无结果 → `/pending` 补答案          | 被动式，必须先有用户提问且未命中                     |

知识库管理页 `/kb` 只有「搜索 / 删除 / 同步」，**没有主动新增、编辑、批量导入入口**。

由此导致两个核心诉求无法满足：

1. **缺失外部知识库**：没有可直接灌入 FAQ/文档的外部来源方式；
2. **无法人工补充**：管理员无法直接录入、编辑问答内容。

***

## 二、方案总览

在原架构上补齐四个「内容补充渠道」，同时保留现有能力：

| 渠道                      | 方式                | 是否新增代码   | 持久化保障                  |
| ----------------------- | ----------------- | -------- | ---------------------- |
| A. 手动新增/编辑问答            | Web 表单直接录入/改问答    | 新增       | `manual_qa` 表持久化，同步不丢失 |
| B. CSV 批量导入 FAQ         | Web 页面粘贴 CSV 批量灌入 | 新增       | `manual_qa` 表持久化，同步不丢失 |
| C. 本地 Markdown / Git 仓库 | 配置后触发同步           | 已有，补操作说明 | 源码在仓库/目录               |
| D. 待补充问题闭环              | 无结果自动入待补充，人工补答案   | 保留原逻辑    | `pending_questions` 表  |

> 渠道 A / B 是本次重点，直接解决「人工补充」；渠道 C 解决「外部知识来源」；渠道 D 保持不变。

***

## 三、代码改动点（已实现）

### 3.1 数据模型 `src/models/db.py`

新增 `manual_qa` 表，作为手动/导入问答的**持久化来源**（`kb_docs` 全量重建后据此回灌）：

```sql
CREATE TABLE IF NOT EXISTS manual_qa (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,      -- 问题/标题
    answer TEXT NOT NULL,     -- 答案
    source TEXT NOT NULL DEFAULT 'manual',  -- manual / import
    created_at TEXT NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT
);
```

### 3.2 知识入库 `src/kb/git_sync.py`

- 新增 `build_qa_doc(title, answer, source, doc_id)`：通用问答片段构造（原 `build_pending_doc` 改由其委托）。

- 新增 `load_manual_docs(db_path)`：读取 `manual_qa` 供同步回灌。

- 新增 `insert_manual_qa` / `update_manual_qa`：持久化表写入与更新。

- 新增 `insert_qa`：单条问答写入 `kb_docs`（按 `doc_id` 先删后插，防重复）。

- 新增 `parse_faq_csv`：解析「问题,答案」两列 CSV。

- `sync_and_ingest` 回灌 `pending` 与 `manual_qa` 两类条目，**同步重建不再丢失人工录入内容**。

### 3.3 Web 路由 `src/web/routes.py`

| 路由                   | 方法         | 功能                                         |
| -------------------- | ---------- | ------------------------------------------ |
| `/kb/new`            | GET / POST | 手动新增单条问答                                   |
| `/kb/import`         | GET / POST | CSV 批量导入                                   |
| `/kb/{rowid}/edit`   | GET / POST | 编辑问答（manual/import 来源同步写 `manual_qa`）      |
| `/kb/{rowid}/delete` | POST       | 删除（manual/import 来源级联删 `manual_qa`，防止同步复活） |

### 3.4 模板 `src/web/templates/`

- `kb.html`：顶部新增「新增问答」「批量导入」按钮，行尾新增「编辑」按钮。

- `kb_form.html`（新增）：新增/编辑共用表单（问题 + 答案）。

- `kb_import.html`（新增）：批量导入表单 + 格式说明。

## 四、操作流程

### 4.1 渠道 A：手动新增问答

1. 浏览器进入 `http://<服务器IP>:8080/kb`；
2. 点击右上角「**新增问答**」；
3. 填写「问题 / 标题」与「答案 / 内容」；
4. 点击「保存」，自动写入 `manual_qa` 并立即进入 `kb_docs` 可被检索。

### 4.2 渠道 A：编辑问答

1. 在知识库列表找到目标片段，点击行尾「**编辑**」；
2. 修改问题或答案后「保存修改」。

> 注意：编辑仅对「manual / import」来源**持久生效**；「Git / 本地 / pending」来源的编辑会在下次同步时被源头数据覆盖，应回到源头（MD 文件、待补充页）修改。

### 4.3 渠道 B：CSV 批量导入 FAQ

1. 进入 `/kb/import`；
2. 按格式粘贴内容（每行 `问题,答案`，首行可为表头）：

   ```csv
   question,answer
   如何请假,请提交 OA 请假申请
   报销流程,填写报销单后提交财务
   ```
3. 点击「导入」，逐条写入 `manual_qa`（source=`import`）并入库。

### 4.4 渠道 C：本地 Markdown / Git 仓库

在 `config.yaml` 二选一：

```yaml
kb:
  repo_url: ""                  # 方式一：Git 仓库地址
  repo_path: "docs"             # 方式二：本地 MD 目录（相对项目根或绝对路径）
```

1. 配置好 `repo_url` 或 `repo_path`；
2. 进入 `/kb` 点击「触发同步」（或重启后触发）；
3. 后台 `sync_and_ingest` 同步 → 按标题/长度切分 → bigram 建索引 → 全量重建 `kb_docs`，并**回灌** pending 与 manual/import 条目。

### 4.5 渠道 D：待补充问题闭环（保留）

1. 用户提问未命中 → 自动写入 `pending_questions`；
2. 管理员进入 `/pending` →「待处理」；
3. 填写答案并「提交答案」→ 标记 resolved、写入 `kb_docs`。

***

## 五、数据持久化与同步说明（重要）

- `kb_docs` 是**可重建的检索索引**；真正持久化来源是 `pending_questions`、`manual_qa` 与仓库目录。

- 每次「触发同步」会 `DELETE FROM kb_docs` 后重建，因此：

  - 手动/导入问答存于 `manual_qa`，同步后自动回灌，**不会丢失**；

  - 待补充已答存于 `pending_questions`，同步后回灌，**不会丢失**；

  - Git/本地文档以仓库/目录为源，修改请改上游文件。

- 删除手动/导入问答时，会同步删除 `manual_qa` 记录，避免下次同步「复活」。

***

## 六、CSV 格式约定

- 分隔符：英文逗号 `,`；

- 列：第一列「问题」，第二列「答案」；

- 首行可为表头（`question,answer` / `问题,答案` / `标题`），自动跳过；

- 内容含逗号/换行时用英文双引号 `"` 包裹；

- 空行、缺列行自动跳过并记录日志。

***

## 七、验收标准

1. `/kb` 可新增问答，保存后立即可检索命中；
2. `/kb` 可编辑问答，manual/import 来源编辑后触发同步不丢失；
3. `/kb/import` 可按 CSV 批量导入，入库条数正确；
4. 删除 manual/import 条目后，触发同步不会复活该条目；
5. 触发同步后，pending 补充答案、手动/导入问答均完整回灌；
6. 代码符合规范：中文注释、参数化 SQL、try/except 指定异常类型、单函数 ≤ 50 行。
