## 一、业务目标与边界

本阶段实现**企微接入层**（`src/wecom/`），建立到企业微信的 WebSocket 长连接，接收用户消息回调，按 `chattype` 分流。

**目标**：
1. 自建 WebSocket 长连接客户端：连接、订阅、心跳、断线重连；
2. 接收消息回调 `aibot_msg_callback` 并解析；
3. 基于 `body.msgid` 做消息排重（防网络重试重复处理）；
4. 按 `chattype` 分流：`single` → 单聊直答入口；`group` → 群聊聚合入口；
5. 提供被动回复（`aibot_respond_msg`）与主动推送（`aibot_send_msg`）能力，含 3 条并发队列控制；
6. 处理企微 3 条消息并发硬限制。

**边界**：本阶段只做接入与分流，检索/聚合业务逻辑由阶段 4/5 实现，本阶段通过接口占位串联；事件回调（enter_chat 等）仅记录日志，不处理业务。

**依赖变更**：因企微长连接为 WebSocket 协议，且 base.md 依赖清单无 WebSocket 客户端库，**经用户确认新增依赖 `websockets`**（企微官方 Python SDK 同样基于该库）。

## 二、协议要点（以官方文档为准）

| 要点 | 说明 |
| --- | --- |
| 连接地址 | `wss://openws.work.weixin.qq.com` |
| 连接数限制 | 每个机器人同一时间**只能一个有效长连接**，新连接踢旧连接 |
| 订阅命令 | `aibot_subscribe`：`{cmd, headers.req_id, body:{bot_id, secret}}` |
| 消息回调 | `aibot_msg_callback`：`headers.req_id`（回复透传）、`body.msgid`（排重）、`body.aibotid`、`body.chatid`（仅群聊）、`body.chattype`（single/group）、`body.from.userid`、`body.msgtype`、`body.text.content` |
| 支持消息类型 | text / image(仅单聊) / mixed / voice(仅单聊) / file(仅单聊) / video(仅单聊) |
| 事件回调 | `aibot_event_callback`：enter_chat / template_card_event / feedback_event / disconnected_event |
| 回复普通消息 | `aibot_respond_msg`：`headers.req_id` 透传回调 req_id，`body.msgtype=text/markdown/...` |
| 主动推送 | `aibot_send_msg`：无回调触发时主动向会话推送 |
| 心跳 | 开发者定期发 `ping`，官方建议间隔 30 秒 |
| 回复时限 | 收到消息回调后 24 小时内可回复该会话 |
| 频率限制 | 每会话 30 条/分钟、1000 条/小时 |
| 并发限制 | 用户与同一机器人最多同时 3 条消息交互中，需队列控制 |

## 三、模块设计

### 3.1 `src/wecom/callback.py` — 长连接客户端

职责：连接管理、订阅、心跳、断线重连、接收回调、msgid 排重、回调解析。

| 接口 | 说明 |
| --- | --- |
| `class CallbackClient` | 长连接客户端 |
| `CallbackClient.start()` | 启动连接循环（订阅 → 接收 → 心跳） |
| `CallbackClient.stop()` | 停止连接 |
| `CallbackClient._on_message(raw)` | 处理服务端消息（订阅响应 / 消息回调 / 事件回调 / pong） |
| `CallbackClient._handle_msg(body, req_id)` | 处理消息回调：msgid 排重后转 dispatcher |

关键逻辑：

```
连接 wss → 发 aibot_subscribe（req_id=uuid）→ 收到 errcode=0 订阅成功
→ 循环接收：
   ├─ cmd=aibot_msg_callback  → msgid 去重 → dispatcher.dispatch(body, req_id)
   ├─ cmd=aibot_event_callback→ 记录日志（enter_chat/disconnected 等）
   └─ 其他/pong            → 忽略或更新心跳状态
→ 每 30 秒发 ping 心跳
→ 断线 → 指数退避重连（1s→2s→...→30s 封顶）
```

**msgid 排重**：使用有界内存去重（`set + deque`），记录最近 N 个 msgid，命中则丢弃并记日志。因服务长期运行，采用有界结构避免内存膨胀。

### 3.2 `src/wecom/dispatcher.py` — chattype 分流

职责：接收解析后的消息，按 `chattype` 分发到单聊/群聊处理链路。

| 接口 | 说明 |
| --- | --- |
| `dispatch(body, req_id)` | 分流入口：按 `body.chattype` 分发 |
| `_dispatch_single(body, req_id)` | 单聊：直接进入检索应答（阶段 5 接入） |
| `_dispatch_group(body, req_id)` | 群聊：进入聚合引擎（阶段 4 接入） |

分流逻辑：

```
dispatch(body, req_id):
    msgtype 非 text/mixed/voice 转文本 → 记录日志并忽略（仅支持可转文本的类型）
    chattype == 'single' → 单聊直答（聚合不适用，直接检索）
    chattype == 'group'  → 群聊聚合（进入 buffer 时间窗）
    其他 → 记录日志忽略
```

> 注：本阶段 dispatcher 内部调用下游模块的**占位处理函数**（阶段 4/5 实现后替换为真实逻辑），保证链路可运行、可测试。

### 3.3 `src/wecom/client.py` — 回复与推送

职责：被动回复（`aibot_respond_msg`）与主动推送（`aibot_send_msg`），承载 3 条并发队列控制。

| 接口 | 说明 |
| --- | --- |
| `class ReplyClient` | 回复客户端，持有 WebSocket 发送通道 |
| `ReplyClient.reply(req_id, content)` | 被动回复文本：`aibot_respond_msg`，透传 req_id |
| `ReplyClient.push(msg)` | 主动推送：`aibot_send_msg` |
| `ReplyClient._queue_control()` | 每会话并发控制：同会话在途消息 ≤ 3 |

队列控制逻辑：

```
以 chatid/userid 为键维护在途计数；新消息入队前检查在途 < 3，
超限则等待前一消息完成（asyncio 信号量/队列），保证不突破企微 3 条并发硬限制。
```

## 四、回调解析数据结构

```python
# 解析后的统一消息结构（dict）
{
    "msgid": str,        # body.msgid，排重依据
    "req_id": str,       # headers.req_id，回复时透传
    "aibotid": str,      # body.aibotid
    "chatid": str | None,# body.chatid，仅群聊返回
    "chattype": str,     # body.chattype: single / group
    "userid": str,       # body.from.userid（可能为加密值，原样使用）
    "msgtype": str,      # body.msgtype
    "content": str,      # 文本内容（text.content / mixed / voice 转文本）
}
```

## 七、验收标准

1. 能建立到 `wss://openws.work.weixin.qq.com` 的连接并完成 `aibot_subscribe` 订阅；
2. 收到 `aibot_msg_callback` 能正确解析出统一消息结构；
3. 相同 `msgid` 重复回调只处理一次；
4. `chattype=single/group` 正确分流到对应处理入口；
5. 被动回复透传 `req_id`，同一会话在途消息 ≤ 3；
6. 断线后按指数退避自动重连，心跳保持连接；
7. 代码符合规范：中文注释、try/except 指定异常类型、单函数 ≤ 50 行。
