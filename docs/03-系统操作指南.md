# 03-系统操作指南

> 版本：v0.1（收尾阶段）
> 说明：本文档面向运维/管理员，涵盖系统配置详解、知识库管理、待补充问题处理、日志、备份与升级。

***

## 一、Web 管理界面入口

启动后访问 `http://<服务器IP>:8080/`，共四个页面：

| 页面     | 路由            | 用途                       |
| ------ | ------------- | ------------------------ |
| 概览     | `/`           | 知识片段数、待补充问题状态统计、快捷入口    |
| 知识库管理 | `/kb`         | 片段列表、关键词搜索、删除、触发同步      |
| 待补充问题 | `/pending`    | 按状态查看问题、补充答案并标记已处理       |
| 系统参数  | `/config`     | 编辑动态配置键，保存写入 sys_config |

> MVP 未实现登录鉴权（内网本地工具），如需对外暴露请自行加反向代理鉴权。

***

## 二、系统配置项详解

配置来源有三层，优先级从低到高：`DEFAULT_CONFIG`（代码内置）→ `config.yaml` → `sys_config`（Web 保存）。

### 2.1 回复相关

- `reply.prefix`：每条回复前缀，默认 `[AI自动回复]：`。
- `reply.no_answer`：检索无结果或低置信度时的温和话术。

### 2.2 聚合相关

- `aggregate.window_seconds`：群聊中同一用户连续消息聚合为完整问题的时间窗（秒），默认 30。
- `aggregate.mention_targets`：@ 触发目标列表（机器人名称 / BotID），为空时回退到 `wecom.bot_id`。

### 2.3 检索相关

- `retriever.score_threshold`：BM25 相关度阈值（默认 0.3），低于此值判定为无结果并记录待补充问题。
- `retriever.top_k`：召回候选条数，默认 5，最终取 top1 回复。

### 2.4 系统参数页可编辑键

`GET /config` 页面预置可编辑键：`reply.prefix`、`reply.no_answer`、`aggregate.window_seconds`、`retriever.score_threshold`、`retriever.top_k`。保存后写入 `sys_config`，**重启进程生效**。

## 三、知识库管理

### 3.1 同步入库

方式一（推荐）：Web「知识库管理」页点击「触发同步」，后台调用 `sync_and_ingest` 全量重建。

方式二：配置好 `kb.repo_url`（Git 仓库）或 `kb.repo_path`（本地目录），启动后通过 Web 触发。

入库流程：同步/扫描 → 按标题与长度切分 → 中文 bigram 切分建索引 → 全量重建 `kb_docs`。

> 全量重建会先 `DELETE FROM kb_docs` 再插入，属预期行为。

### 3.2 搜索与删除

- 搜索：知识库页关键词框输入后按 FTS5 MATCH 检索（复用 bigram 切分）。
- 删除：每条片段右侧「删除」按钮，按 `rowid` 删除单条。

***

## 四、待补充问题处理流程

1. 用户提问检索不到时，自动写入 `pending_questions` 表（`status=pending`）。
2. 进入「待补充问题」页，切换「待处理」筛选。
3. 在问题卡片输入答案并「提交答案」，记录 `status=resolved` 并保存 `answer`。
4. 如需让机器人学会该问题，需将答案整理进知识库文档后重新同步（见 3.1）。

***

## 五、日志查看

- 日志输出到标准输出，格式：`时间 | 级别 | 模块 | 消息`。
- `nohup` 后台运行时重定向至 `logs/web.log`。
- 关键日志模块：`wecom.callback`（长连接/排重）、`retriever.fts5`（检索命中）、`kb.git_sync`（同步）、`web.routes`（界面操作）。

***

## 六、数据库备份与恢复

SQLite 单文件数据库，路径见 `storage.db_path`（默认 `data/kb.db`）。

备份（需先停写，或使用 SQLite 在线备份命令）：

```bash
cp data/kb.db data/kb.db.bak-$(date +%F)
```

或在运行中执行一致性备份：

```bash
sqlite3 data/kb.db ".backup 'data/kb_backup.db'"
```

恢复：

```bash
# 停止服务后覆盖
cp data/kb.db.bak-YYYY-MM-DD data/kb.db
```

> 数据库表：`kb_docs`（FTS5 知识片段）、`pending_questions`（待补充问题）、`sys_config`（动态配置）。

## 七、版本升级步骤

1. 备份数据库（见第六节）。
2. 拉取最新代码（禁止 push，仅在 main 分支）。
3. 重新安装依赖（如 requirements.txt 有变更）：`pip install -r requirements.txt`。
4. 覆盖 `config.yaml`（如有新配置项，参考 `config.yaml.example` 差异）。
5. 重启服务：`cd src && uvicorn main:app ...`。
6. 首次启动会自动执行数据库迁移（如 `kb_docs` 缺 `raw_content` 列时自动重建）。

> 数据库迁移：`src/models/db.py` 的 `_migrate_kb_docs` 检测表结构，缺列时重建（知识库数据由后续同步全量重建，属预期）。
