## 一、业务目标与边界

本阶段实现**知识入库流水线**（`src/kb/git_sync.py`）：把 Git 仓库（或本地目录）中的 Markdown 文档同步、切分、入库到 `kb_docs`，供阶段 5 检索应答使用。

**目标**：

1. 从配置的 Git 仓库 clone/pull（或扫描本地目录）获取 MD 文档；
2. 将文档按语义切分为片段（chunk），提取 title/source/doc\_id；
3. 内容经中文 bigram 切分后写入 `kb_docs`，保证阶段 5 检索可用；
4. 支持来源级全量重建，保证知识库与仓库一致。

**边界**：本阶段不实现微信聊天记录清洗（`wechat_clean.py` 暂缓）；不涉及 Web 界面触发（阶段 7 接入）；Git 操作用系统 `git` 命令（subprocess），不引入第三方 Git 库。

***

## 二、关键设计决策

### 2.1 修正：索引文本与原文分离（需同步小改阶段 2/5）

阶段 5 的检索在 `kb_docs` 上做 MATCH，若 content 直接存 bigram 切分文本（"报销 销流 流程"），命中后回复/展示会露出切分文本，不可接受。

**修正方案**：调整 `kb_docs` FTS5 表结构，增加原文列，索引文本与原文分离：

```sql
CREATE VIRTUAL TABLE kb_docs USING fts5(
    title UNINDEXED,          -- 原文标题（仅存储，不参与全文索引）
    content,                  -- bigram 切分后的索引文本（参与全文索引）
    source UNINDEXED,         -- 文档来源相对路径
    doc_id UNINDEXED,         -- 文档片段唯一标识
    raw_content UNINDEXED,    -- 片段原文（回复/展示用）
    tokenize = 'unicode61'
);
```

- **迁移**：`init_db` 检测 `kb_docs` 是否含 `raw_content` 列，缺失则 `DROP TABLE kb_docs` 后按新结构重建（数据由下次同步全量重建，成本低）。

- **阶段 5 配套修改**：

  - `fts5.py::search` 的 SELECT 增加 `raw_content` 列；

  - `responder.py` 回复正文取 `hits[0]["raw_content"] or hits[0]["title"]`。

### 2.2 同步策略

- `kb.repo_url` 非空 → **Git 模式**：首次 `git clone --depth 1 -b <branch>`，已存在则 `git -C <work_dir> pull --ff-only`；

- `kb.repo_url` 为空但 `kb.repo_path` 非空 → **本地目录模式**：直接扫描本地目录；

- 两者皆空 → 记录日志并跳过同步。

- 所有 git 外部调用 subprocess + try/except + 超时，失败记录日志不中断主流程。

### 2.3 入库策略：来源级全量重建

每次同步后清空 `kb_docs` 再按序插入全部片段（单事务），保证与仓库完全一致。MVP 不做文件级增量，后续可优化为按文件 hash 增量更新。

### 2.4 切分策略

- 按 Markdown 标题（行首 `# ` \~`###### ` ）优先切分，保持片段语义完整；

- 片段字符数达 `kb.chunk_size`（默认 500）时切出，`kb.chunk_overlap`（默认 50）尾部重叠；

- `title` 取文档首个一级标题（无则取文件名）；`doc_id` 取 `{source}:{序号}`，稳定唯一。

## 四、关键代码逻辑（伪代码）

```python
def split_markdown(text, chunk_size, chunk_overlap):
    chunks, buf = [], []
    for line in text.splitlines():
        if line.startswith("#") and buf:          # 标题开启新片段
            chunks.append("\n".join(buf))
            buf = []
        buf.append(line)
        while sum(len(x) for x in buf) >= chunk_size and len(buf) > 1:
            buf = _cut_chunk(buf, chunks, chunk_overlap)  # 按行切出，尾部重叠
    if buf:
        chunks.append("\n".join(buf))
    return [c.strip() for c in chunks if c.strip()]


def build_docs(file_path, chunk_size, chunk_overlap):
    raw = read_text(file_path)                     # 读取 MD 原文
    title = extract_title(raw) or basename(file_path)
    docs = []
    for idx, chunk in enumerate(split_markdown(raw, chunk_size, chunk_overlap)):
        docs.append({
            "title": title,
            "content": " ".join(segment_bigrams(chunk)),  # 复用阶段5切分
            "source": relative_path(file_path),
            "doc_id": f"{relative_path(file_path)}:{idx}",
            "raw_content": chunk,
        })
    return docs


def ingest_docs(db_path, docs):
    with get_connection(db_path) as conn:          # 单事务
        conn.execute("DELETE FROM kb_docs")
        for doc in docs:
            conn.execute(
                "INSERT INTO kb_docs (title, content, source, doc_id, raw_content) "
                "VALUES (?, ?, ?, ?, ?)",
                (doc["title"], doc["content"], doc["source"], doc["doc_id"], doc["raw_content"]),
            )
    return len(docs)
```

## 七、验收标准

1. 配置本地 MD 目录后 `sync_and_ingest` 能把文档切分入库，返回片段数；
2. `kb_docs` 含 `raw_content` 列，content 为 bigram 切分文本、raw\_content 为原文；
3. 已存在的旧结构库可自动迁移重建（`raw_content` 列缺失时）；
4. 阶段 5 检索命中后返回原文而非切分文本（responder 取 raw\_content）；
5. 重跑同步为全量重建，无残留旧片段；
6. git 失败/目录不存在等异常被捕获并记录日志，不中断进程；
7. 代码符合规范：中文注释、参数化 SQL、try/except 指定异常类型、单函数 ≤ 50 行。
