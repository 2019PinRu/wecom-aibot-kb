# 08-Skill 文档编写规范

> 版本：v1.0
> 说明：本文档定义本系统可解析的 **SKILL.md** 标准格式，供其他 agent / 人员按要求生成技能文档，确保一次通过解析并正确入库、可被检索命中。

***

## 一、目的与适用范围

本系统（`wecom-aibot-kb`）的知识入库流水线（`src/kb/git_sync.py`）会识别技能定义文档并解析为可检索的知识片段。规范用于约束：

- 文件**命名与目录结构**；

- 文件**头部 YAML frontmatter** 的字段与格式；

- **正文**的组织与格式。

只有符合本规范的文档，才能被识别为 Skill（`title` 取技能名、`description` 纳入检索索引）；不符合则回退为普通 Markdown（仅按首个 `#` 标题切分，损失技能语义）。

***

## 二、目录与命名规范

| 项    | 要求                                               |
| ---- | ------------------------------------------------ |
| 目录   | `skills/<技能名>/SKILL.md`                          |
| 文件名  | 必须为 `SKILL.md`（不区分大小写）                           |
| 相对路径 | 最终作为片段的 `source`，建议保持 `skills/<技能名>/SKILL.md` 结构 |

示例：

```
skills/
└── sfhis-core-inhospital-drug-solve/
    └── SKILL.md
```

> 系统仅按 basename 是否为 `skill.md` 判定 Skill 文档；目录名建议与 frontmatter 的 `name` 保持一致。

***

## 三、Frontmatter 规范（关键）

文件**首行必须为** **`---`**，以 `---`（或 `...`）结束 YAML 块，其后为 markdown 正文。

```markdown
---
name: <技能名>
description: <技能描述>
---
# 正文标题
正文……
```

### 3.1 字段说明

| 字段            | 必填   | 用途            | 说明                             |
| ------------- | ---- | ------------- | ------------------------------ |
| `name`        | ✅ 是  | 片段标题（`title`） | 小写字母/数字/连字符，技能唯一标识             |
| `description` | ⭐ 建议 | 检索索引          | 描述技能做什么、何时使用；系统会将其与正文一起切分建索引   |
| `version`     | 否    | 版本            | 仅记录，参与索引的是 name/description/正文 |
| `type`        | 否    | 类型            | 仅记录                            |
| `scene`       | 否    | 场景            | 仅记录                            |

> `name` 缺失或为空时，系统**不会**按 Skill 解析，而是回退为普通 Markdown。

### 3.2 写法约定

- `description` 是最重要的检索字段，请**用一句话说清**：技能针对什么问题、解决什么场景。

- 若 `description` 内含半角冒号 `:`、井号 `#` 或换行，请用双引号包裹或 `>` 折叠块标量：

```yaml
description: >-
  用户在 SFHIS Core 系统遇到住院药品医嘱停嘱失败、
  领药单生成失败等问题时，自动匹配标准排查步骤与解决方案。
或
description: "用户在系统遇到停医嘱失败、领药单生成失败等问题时自动匹配解决方案"
```

***

## 四、正文规范

### 4.1 标题分层

- 用 `#` ～ `######` 标题组织层级；系统会**按标题切分片段**。

- FAQ 类技能，**每个问题用三级标题**（`### Q1：…`），使每个问答独立成一个片段，检索更精准。

### 4.2 内容写法

| 建议               | 说明                          |
| ---------------- | --------------------------- |
| 用 `1.` `2.` 有序列表 | 不要用 `\1.`、`●`、`•`           |
| 分点写「标准解决方案」      | 便于切分后仍语义完整                  |
| 同义提问可单列一行        | 如 `同义提问：停医嘱失败、停不掉`，纳入索引提升命中 |
| 禁止零宽字符           | U+200B 等零宽字符会打断中文分词，必须清除    |

### 4.3 完整模板

```markdown
---
name: sfhis-core-inhospital-drug-solve
version: "1.0"
description: 用户在SFHIS Core系统遇到住院药品医嘱停嘱失败、领药单生成失败、药品未计费等问题时，自动匹配标准排查步骤与解决方案。
type: 故障排查｜问答解决方案
scene: SFHIS Core 住院护士站、药房药品医嘱操作场景
---

# 技能中文标题

## 一、技能执行强制规则

1. 规则一。
2. 规则二。

## 二、核心FAQ问答库

### Q1：问题一句话描述

同义提问：近义词、口语化同义句

故障原因：简述原因

标准解决方案：

1. 步骤一。
2. 步骤二。

### Q2：问题二描述

……

## 三、异常兜底规则

1. 兜底规则一。
2. 兜底规则二。
```

## 五、系统解析规则（对照）

| 环节          | 规则                                                             |
| ----------- | -------------------------------------------------------------- |
| 识别          | basename（忽略大小写）为 `skill.md`                                    |
| frontmatter | 首行 `---`，结束为 `---` / `...`；`yaml.safe_load` 解析为 dict；`name` 非空 |
| 标题          | `title = name`                                                 |
| 索引          | `content = bigram(name + description + 正文片段)`                  |
| 切分          | 按标题 + `kb.chunk_size` 长度切分                                     |
| 原文          | `raw_content = 正文片段`（检索命中后回复展示用）                               |
| 来源          | `source = 相对路径`；`doc_id = 相对路径:序号`                             |

***

## 六、生成后自查清单

- [ ] 文件名是否为 `SKILL.md`（位于 `skills/<name>/` 下）

- [ ] 首行是否为 `---`，frontmatter 是否能被 YAML 解析

- [ ] `name` 已填写且非空（小写字母/数字/连字符）

- [ ] `description` 一句话说清技能用途

- [ ] FAQ 每个问题用 `###` 标题

- [ ] 无零宽字符、无 `\1.` 反斜杠编号

- [ ] 正文标题用 `#` 系列，非 `**加粗**` 冒充标题

***

## 七、常见错误

| 错误写法                   | 问题               | 正确写法                    |
| ---------------------- | ---------------- | ----------------------- |
| 文件名 `技能说明.md`          | 无法识别为 Skill      | 重命名为 `SKILL.md`         |
| 元信息写在正文 `## 技能元信息` 章节  | frontmatter 解析失败 | 移到文件头 `---` frontmatter |
| `name` 留空              | 回退普通 Markdown    | 填写技能名                   |
| `description` 含半角冒号未引号 | YAML 解析异常        | 用双引号或 `>` 块             |
| 用 `**Q1：…**` 粗体当标题     | 无法按标题切分          | 改用 `### Q1：…`           |
