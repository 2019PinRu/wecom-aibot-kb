## 一、业务目标与边界

本阶段实现**检索应答引擎**（`src/retriever/`），完成"问题 → 本地知识库检索 → 置信度判定 → 回复格式化 / 无结果记录"的应答闭环。

**目标**：
1. 用 SQLite FTS5 全文检索从 `kb_docs` 召回候选；
2. 用 `-bm25()` 评分并对照 `retriever.score_threshold` 做置信度判定；
3. 命中：拼接 `reply.prefix` 前缀（群聊再追加 `@提问人`）后被动回复；
4. 未命中 / 低置信度：不转人工，原始问题写入 `pending_questions` 表，返回 `reply.no_answer` 话术；
5. 提供单聊直答与群聊聚合完成两条链路的统一入口。

**边界**：本阶段只做检索与回复格式化，不涉及知识入库（阶段 6）与 Web 界面（阶段 7）；消息发送复用阶段 3 的 `ReplyClient`。

## 二、核心算法：FTS5 检索与置信度判定

### 2.1 中文分词方案（关键设计决策）

SQLite FTS5 内置 `unicode61` 分词器**不识别中文分词**，"企业微信"会被当作一个 token，检索"微信"将无法命中。

解决方案：入库前与查询前统一做**字符二元组（bigram）切分**，再交给 `unicode61` 逐 token 索引：
- "企业微信" → `企业 业微 微信`
- 查询"微信" → 同样切分为 bigram `微信`，与索引 token 精确匹配

> 说明：bigram 切分效果需在真实语料联调中校准；若召回率不理想，可切换为字符级切分或引入 jieba（需新增依赖）。标注待验证。

### 2.2 检索与评分

```
构建 MATCH 表达式：
1. 对问题文本做 bigram 切分，得到词项列表 terms
2. terms 为空 → 返回空结果
3. 生成 "term1" OR "term2" OR ... 的 MATCH 表达式（OR 保证召回）

执行检索：
SELECT title, content, source, doc_id, -bm25(kb_docs) AS score
FROM kb_docs
WHERE kb_docs MATCH ?
ORDER BY bm25(kb_docs)        -- 升序：值越小越相关，最相关的排最前
LIMIT ?

置信度判定：
- score = -bm25()，值越大越相关
- score >= retriever.score_threshold（默认 0.3）→ 命中
- 否则视为无结果（低置信度）
```

### 2.3 回复格式化

- 单聊：`prefix + 答案正文`
- 群聊：`@提问人 ` + `prefix + 答案正文`（@强提醒变通，见 base.md 硬约束）
- 命中答案取 top1 的 `content`（为空时回退 `title`）
- 无结果：不转人工，写入 `pending_questions` 后返回 `reply.no_answer` 话术

> 说明：`score_threshold` 的绝对数值依赖 bm25 输出量级，需在联调中校准（标注待验证）。

## 四、关键代码逻辑（伪代码）

```python
def search(db_path, question, top_k, score_threshold):
    match_expr = build_match_query(question)
    if not match_expr:
        return []
    sql = (
        "SELECT title, content, source, doc_id, -bm25(kb_docs) AS score "
        "FROM kb_docs WHERE kb_docs MATCH ? "
        "ORDER BY bm25(kb_docs) LIMIT ?"
    )
    rows = query(db_path, sql, (match_expr, top_k))
    return [r for r in rows if r["score"] >= score_threshold]


async def handle_question(question, req_id, meta):
    # meta 字段：chattype / chatid / userid / asker
    hits = search(db_path, question, config.top_k, config.score_threshold)
    if not hits:
        await self._record_pending(question, meta)
        content = config.no_answer
    else:
        content = hits[0]["content"] or hits[0]["title"]
    text = format_reply(config.prefix, content, meta["chattype"], meta.get("asker"))
    await self._reply_client.reply(req_id, text)
```

> 并发安全：检索与回复均在单事件循环内串行执行；发送复用 `ReplyClient` 的会话信号量（同一会话 ≤ 3 条在途）。

## 七、验收标准

1. 空库或无关问题检索返回空，问题写入 `pending_questions`，回复 `no_answer` 话术；
2. 命中问题返回 top1 答案，前缀正确拼接；群聊回复以 `@提问人 ` 开头；
3. 中文问题（如"报销流程"）能召回含该词的知识片段（bigram 生效）；
4. 低于 `score_threshold` 的弱匹配不回复答案，按无结果处理；
5. `pending_questions` 记录含 question / asker / chattype / chatid；
6. 代码符合规范：中文注释、参数化 SQL、try/except 指定异常类型、单函数 ≤ 50 行。
